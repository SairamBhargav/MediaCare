# Capability matrix

What the app can actually do, where, and on what evidence. Update a row whenever evidence changes; never upgrade a status without recording the evidence.

**Statuses**

| Status                       | Meaning                                                                                 |
| ---------------------------- | --------------------------------------------------------------------------------------- |
| `verified-on-device`         | Exercised on a physical iPhone; device, iOS, SDK, build type and date recorded          |
| `verified-local`             | Checked by automated tooling on Windows (typecheck, tests, bundle). Not device evidence |
| `documented-not-tested`      | Official versioned docs say it works; nobody has run it on a device                     |
| `spike-required`             | Unknown; a time-boxed experiment must answer it before anything depends on it           |
| `development-build-required` | Needs native code or config Expo Go cannot load                                         |
| `deferred`                   | Planned for a later phase                                                               |
| `unsupported`                | Known not to be possible with the chosen approach                                       |

Environment at bootstrap: Expo SDK 57 · React Native 0.86.3 · Windows 11 dev machine · **no device test yet** (2026-10-02).

## Feasibility spikes

Each spike is time-boxed, produces a short report in `docs/spikes/`, and updates this table.

| ID  | Question                                                                                            | Method                                                                                                                                                                               | Pass criteria                                                                                                     |
| --- | --------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------- |
| S1  | Can we read the **original resource bytes** of a Photos asset and hash them with bounded memory?    | Disposable test album: JPEG, HEIC, edited photo, Live Photo, iCloud-optimized photo. Compare `getUri()` bytes against AirDrop/export of the original; measure memory on a 50 MB file | Byte-identical to the original for each type, or a documented list of types where it is not; memory stays bounded |
| S2  | Can we get downscaled pixels for analysis off the UI thread?                                        | Prototype in Expo Go (manipulator → small PNG → decode) vs native module                                                                                                             | Deterministic 64×64 grayscale buffer, < 50 ms/photo on baseline device, no UI hitches                             |
| S3  | Do HEIC, rotated JPEG, panoramas, screenshots and iCloud-only assets display correctly in the grid? | Fixture album on device                                                                                                                                                              | Correct orientation and color; placeholder state for undownloaded originals                                       |
| S4  | What exactly happens when we delete?                                                                | Delete 1 and 3 disposable assets; cancel the dialog; delete with one asset already gone                                                                                              | Recorded system UI, return values, error codes, Recently Deleted contents                                         |
| S5  | What do manipulator exports preserve?                                                               | Export rotated JPEG, transparent PNG, P3 photo, GPS photo                                                                                                                            | Recorded orientation, alpha, color profile, EXIF/GPS behavior, actual byte sizes                                  |
